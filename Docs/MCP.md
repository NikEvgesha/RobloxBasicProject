# MCP Setup

This project uses the AI Game Developer MCP server from the Unity project integration.

Prefer `Custom` connection mode for this repository. The Unity plugin runs a local MCP server and Codex connects to it directly. This avoids sharing the global `GAME_DEV_AUTH_TOKEN` and avoids cloud HubConnection instability.

The server is configured in:

```text
.codex/config.toml
```

Project-local MCP entry:

```toml
[mcp_servers."ai-game-developer-roblox-basic-project"]
enabled = true
startup_timeout_sec = 30
tool_timeout_sec = 300
url = "http://localhost:26124"
```

Do not rename this entry to the generic `ai-game-developer`; that name is already used by other Unity projects on this workstation.

## Project-Specific Token

Custom mode with `Authorization Token: none` does not need a token.

If Cloud mode or required authorization is enabled again, use a project-specific environment variable:

```text
ROBLOX_BASIC_PROJECT_GAME_DEV_AUTH_TOKEN
```

Do not use the shared `GAME_DEV_AUTH_TOKEN` variable for this repository. Other Unity projects may already use that variable, and sharing it makes it easy to connect Codex to the wrong Unity MCP session.

The token must not be committed to Git.

## Codex Desktop Global Config

On this workstation, Codex Desktop also reads MCP servers from the user-level config:

```text
C:\Users\loon1\.codex\config.toml
```

Use a separate server name for this project:

```toml
[mcp_servers."ai-game-developer-roblox-basic-project"]
enabled = true
startup_timeout_sec = 30
tool_timeout_sec = 300
url = "http://localhost:26124"
```

Do not overwrite existing `ai-game-developer` entries. Other projects may already use them.

## Windows Setup

For the current Custom mode setup, no Windows environment variable is required.

Only if Cloud mode or required authorization is enabled, set the user environment variable with the token generated by the Unity MCP window:

```powershell
setx ROBLOX_BASIC_PROJECT_GAME_DEV_AUTH_TOKEN "<token from Unity MCP window>"
```

Restart the Codex terminal or Codex desktop session after setting the variable.

## Unity Side

In Unity, keep the AI agent set to `Codex`, keep Connection set to `Custom`, and use the project-local `.codex/config.toml`.

Expected local MCP URL:

```text
http://localhost:26124
```

If the AI Game Developer window regenerates `.codex/config.toml`, verify it did not replace the project-specific entry with:

```toml
[mcp_servers.ai-game-developer]
bearer_token_env_var = "GAME_DEV_AUTH_TOKEN"
```

For this repository, restore the project-specific entry shown above before restarting Codex.
